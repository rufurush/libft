# libft

C言語の標準ライブラリで頻繁に使われる関数を、基本的な言語機能とシステムコールだけで再実装したライブラリです。

文字判定、文字列・メモリ操作、動的メモリ確保、数値変換、ファイルディスクリプタへの出力など、全34関数を静的ライブラリ`libft.a`としてまとめています。

```c
#include "libft.h"

char *message = ft_strjoin("Hello, ", "libft!");
ft_putendl_fd(message, 1);
free(message);
```

> A custom C library that rebuilds essential libc functions from the ground up.

## このプロジェクトについて

libftは、フランス発のエンジニア養成機関「42」の最初の課題です。普段は当然のように利用する標準ライブラリ関数を自分で実装し、C言語におけるポインタ、配列、文字列、メモリ管理の基礎を身につけます。

この課題で作成したライブラリは、以降の42のC言語プロジェクトでも再利用します。そのため、単に同じ結果を返すだけでなく、境界値、メモリ確保の失敗、領域の重なりといった条件まで考慮し、汎用的な部品として扱えることを意識しました。

## 関数ごとの説明とテストケース

### ft_split — 区切り文字で文字列を分割する

```c
char **ft_split(const char *s, char c);
```

`s`を区切り文字`c`で分割し、各単語を新しく確保した文字列として返します。ここでの「単語」は、区切り文字以外が連続する部分です。区切り文字は1文字で、元の文字列は変更しません。

先頭・末尾の区切り文字や連続する区切り文字は読み飛ばし、空の単語は作りません。例えば`ft_split(",apple,,banana,", ',')`の結果は次のようになります。

```text
result ──→ [0] ──→ "apple\0"
           [1] ──→ "banana\0"
           [2] = NULL
```

戻り値が`char **`なのは、各文字列の先頭を指す`char *`を配列にして返すためです。各文字列の終わりは`'\0'`、ポインタ配列の終わりは`NULL`で表します。

#### 戻り値と入力の条件

- 成功時は、最後の要素が`NULL`のポインタ配列を返します。呼び出し側で各文字列と配列本体を解放します。
- 空文字列や区切り文字だけの入力では、確保に成功すると`{NULL}`を返します。単語は0個ですが、配列本体の解放は必要です。
- メモリ確保に失敗すると`NULL`を返します。途中まで確保した領域は関数内で解放します。
- この実装では、`s == NULL`の場合も`NULL`を返します。これはこの実装の防御的な処理として扱います。

`s`には、読み取り可能で`'\0'`で終わる文字列を渡します。終端のない配列や解放済みのポインタは有効な入力ではありません。

#### 処理の流れ

1. `s == NULL`なら、そのまま`NULL`を返します。
2. `ft_splits_counts`で単語数を数えます。区切り文字を読み飛ばし、単語の先頭が見つかったときだけ数を増やして、その単語の末尾まで進みます。
3. `sizeof(char *) * (split + 1)`バイトを確保します。`split`は単語数で、追加の1個は配列終端の`NULL`用です。
4. `ft_split_fill`でもう一度入力を走査し、各単語の開始位置`start`と、その直後の位置`i`を求めます。
5. `alloc_word`で`i - start + 1`バイトを確保し、単語をコピーします。追加の1バイトには文字列終端の`'\0'`を書き込みます。
6. すべて成功したら`result[split] = NULL`を設定して返します。途中で失敗したら`free_all`で作成済みの単語と配列本体を解放し、`NULL`を返します。

失敗時は配列終端の`NULL`がまだ設定されていないため、`free_all`には作成済みの単語数`index`を渡し、`result[0]`から`result[index - 1]`までを解放します。

入力長を`n`とすると、単語数のカウントとコピーを含めて処理時間は`O(n)`です。確保する領域は、各単語の文字列と単語数＋1個分のポインタです。

#### 使用例とメモリの解放

```c
#include "libft.h"

int main(void)
{
    char    **words;
    size_t  i;

    words = ft_split(",apple,,banana,", ',');
    if (words == NULL)
        return (1);
    i = 0;
    while (words[i] != NULL)
    {
        ft_putendl_fd(words[i], 1);
        free(words[i]);
        i++;
    }
    free(words);
    return (0);
}
```

出力は`apple`と`banana`の2行です。`free(words)`だけでは各単語の領域が残るため、先に`words[i]`をそれぞれ解放します。

#### テストケース

表の`{"a", "b", NULL}`は戻り値の配列の内容を表します。通常ケースはメモリ確保が成功する前提です。戻り値そのものが`NULL`であることと、戻り値の先頭要素が`NULL`であることを区別して確認します。

| 確認したいこと | 呼び出し | 期待する結果 |
| --- | --- | --- |
| 通常の分割 | `ft_split("apple,banana,cherry", ',')` | `{"apple", "banana", "cherry", NULL}` |
| 区切り文字がない | `ft_split("apple", ',')` | `{"apple", NULL}` |
| 先頭・末尾の区切り文字 | `ft_split(",apple,banana,", ',')` | `{"apple", "banana", NULL}` |
| 連続する区切り文字 | `ft_split("apple,,,banana", ',')` | `{"apple", "banana", NULL}` |
| 空文字列 | `ft_split("", ',')` | `{NULL}` |
| 区切り文字だけ | `ft_split(",,,", ',')` | `{NULL}` |
| 1文字の単語 | `ft_split("a", ',')` | `{"a", NULL}` |
| 1文字の区切り文字だけ | `ft_split(",", ',')` | `{NULL}` |
| 空白で分割 | `ft_split("  hello   world  ", ' ')` | `{"hello", "world", NULL}` |
| 指定していない空白文字を保持 | `ft_split("a\tb c", ' ')` | `{"a\tb", "c", NULL}` |
| 区切り文字が`'\0'` | `ft_split("abc", '\0')` | `{"abc", NULL}` |
| 空文字列と`'\0'` | `ft_split("", '\0')` | `{NULL}` |
| 入力途中の`'\0'`で読み取り終了 | `ft_split("a\0,b", ',')` | `{"a", NULL}` |
| `NULL`入力（この実装の動作） | `ft_split(NULL, ',')` | `NULL` |

文字列の内容に加えて、元の入力が変更されていないこと、結果の各文字列が`'\0'`で終わること、配列が`NULL`で終わることも確認します。正常に返された結果は、空の配列も含めて解放します。

#### メモリ確保に失敗する場合のテスト

`ft_split("a,b,c", ',')`では、配列本体と3つの単語のために計4回`malloc`を呼びます。テスト用に`malloc`を差し替え、指定した回だけ`NULL`を返すようにすると、各失敗経路を確認できます。

| 失敗させる確保 | 期待する動作 |
| --- | --- |
| 1回目：配列本体 | `NULL`を返す |
| 2回目：`"a"` | 配列本体を解放し、`NULL`を返す |
| 3回目：`"b"` | `"a"`と配列本体を解放し、`NULL`を返す |
| 4回目：`"c"` | `"a"`、`"b"`と配列本体を解放し、`NULL`を返す |

どの経路でも、メモリリーク・二重解放・解放後のアクセスがないことを確認します。

#### クラッシュにつながる不正な入力

```c
char s[3] = {'a', 'b', 'c'}; /* 終端の '\0' がない */
char **words = ft_split(s, ',');
```

この例では文字列の終わりを探して配列外を読み取るため、未定義動作になります。AddressSanitizerでは範囲外アクセスとして検出できますが、通常実行で必ずクラッシュするとは限りません。これは有効な入力に対する合否テストとは分けて扱います。

#### 何も見ずに実装するときの確認ポイント

- 単語数を増やすのはどのタイミングか。
- 配列の確保と単語の確保で、それぞれなぜ`+ 1`が必要か。
- `c == '\0'`でも文字列の終端を越えない理由を説明できるか。
- 途中で確保に失敗したとき、何個の単語を解放する必要があるか。
- 成功後に、呼び出し側が解放する領域はどれか。

## 実装でこだわった点

### 1. 標準関数の仕様と境界条件を再現する

標準ライブラリに対応する関数は、通常の入力だけでなく、空文字列、長さ0、検索範囲の終端といった境界条件でも本来の仕様に沿うよう実装しました。

例えば`ft_strlcpy`は、コピー先のサイズが0なら書き込みを行わず、コピー元の文字列長だけを返します。戻り値を使うことで、呼び出し側は文字列が切り詰められたかを判定できます。

### 2. 重なったメモリ領域を安全にコピーする

`ft_memcpy`ではコピー元とコピー先が重なる場合の動作は未定義ですが、`ft_memmove`は重なりにも対応する必要があります。

コピー先がコピー元より前にあれば先頭から、後ろにあれば末尾からコピーします。方向を切り替えることで、まだ読み取っていないデータを上書きせずに移動できます。

```text
前方へ移動:  [a b c d e]  -> 先頭からコピー
後方へ移動:  [a b c d e]  -> 末尾からコピー
```

### 3. メモリ確保前に整数オーバーフローを検出する

`ft_calloc`が確保するサイズは`count * size`です。この乗算が`size_t`の上限を超えると、小さな値へ回り込んで想定より狭い領域を確保する危険があります。

そこで、乗算前に`count > SIZE_MAX / size`を確認し、オーバーフローする場合は`NULL`を返します。

### 4. 途中で失敗した確保もすべて解放する

`ft_split`は、分割後の文字列を格納する配列と各単語をそれぞれ動的に確保します。途中の単語で`malloc`が失敗した場合、それまでに作成したすべての文字列と配列本体を解放してから`NULL`を返します。

成功時だけでなく失敗経路まで含めて所有権を整理し、メモリリークを残さない構造にしています。

### 5. 符号付き整数の最小値を特別に扱う

32bitの`int`では、`INT_MIN`の絶対値は`INT_MAX`より1大きく、そのまま正数へ反転できません。`ft_itoa`と`ft_putnbr_fd`ではこの境界値を個別に扱い、オーバーフローを避けています。

また、この実装の`ft_atoi`は、変換結果が`int`の範囲を超える場合に`INT_MAX`または`INT_MIN`を返します。

### 6. ファイルディスクリプタを出力先として扱う

出力関数は標準出力に固定せず、引数で受け取ったファイルディスクリプタへ`write`します。同じ関数を標準出力、標準エラー出力、開いたファイルなどに使えます。

```c
ft_putendl_fd("success", STDOUT_FILENO);
ft_putendl_fd("error", STDERR_FILENO);
```

## ビルドと使用方法

### 必要環境

- Unix系OS（Linux / macOS）
- `cc`
- `make`
- `ar`

### ビルド

```bash
git clone https://github.com/rufurush/libft.git
cd libft
make
```

`-Wall -Wextra -Werror`を有効にして各ソースをコンパイルし、`libft.a`を生成します。

### 自分のプログラムで使用する

```bash
cc main.c -L. -lft -o main
./main
```

使用するソースファイルではヘッダを読み込みます。

```c
#include "libft.h"
```

### クリーンアップ

```bash
make clean   # オブジェクトファイルを削除
make fclean  # オブジェクトファイルとlibft.aを削除
make re      # ライブラリを再ビルド
```
